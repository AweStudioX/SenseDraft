# Manual test pass

1. Launch `build/SenseDraft.app`. In the first-launch Permissions page, grant Accessibility access in macOS System Settings and click **Check again**. If macOS does not recognize the app after rebuilding, remove the old SenseDraft entry and add the current app bundle again. Reopen Settings and confirm the Home page displays the app logo; use the sidebar to open AI Services, Writing, History, Shortcuts, and Permissions. Check each page at the default and minimum window sizes in both light and dark appearance.
2. In AI Services, select a source without enabling it and verify only the right detail pane changes. Enable OpenAI, paste a valid key with ⌘V, choose a model, turn on **Show in results**, and click **Save AI settings**. Confirm the footer shows Saved, the secure field has one masked placeholder without overlapping text, and no real key is exposed. Click **Check connection** and verify a success or concise failure appears; HTTP 429 must say rate limit or quota rather than blaming the key. Add DeepSeek and Kimi keys independently and confirm saved keys survive relaunch and can be removed separately. For Kimi, select China or Global to match the API Key's platform and verify the corresponding endpoint is used. Enable more sources while leaving **Show in results** off for some, then select two or three sources for results. Verify only selected, enabled, configured sources receive requests and appear in the review panel in source order. The panel should show a loading placeholder for each selected source immediately, replace each placeholder as that source finishes, and display every English and Chinese result without switching views. In Writing, choose the English locale and style. Select a later result by clicking an empty area of its card, then edit either result inline and confirm selecting another result does not change what is displayed. With the review panel focused outside an editor, press ↑/↓ to switch between completed results; confirm the selected card scrolls into view, the shortcut stops at either end, skips pending results, and Replace uses the selected result. Press Return with a changed result selected and confirm it replaces the original input; with no changed result, it must not replace. Focus an English or Chinese editor and confirm ↑/↓ moves the text cursor and Return inserts a newline. Check that clicking an editor still edits text and **Copy English** still copies without changing the selected provider. Copy and Replace must use the selected result, including while another source is still loading. Analyze again and confirm the previously selected source becomes selected when its result arrives. Disconnect or remove one source and confirm other configured sources still work. Test one failing source alongside one successful source and confirm the successful result remains usable. Keep the ChatGPT plan sign-in test separate; it requires an eligible account and browser authorization.
   For Kimi K2.6, confirm a short sentence returns both English and Chinese with the fast non-thinking request mode; K3 retains its default mode. For a Kimi 429, confirm the message identifies a recognized error type. Inspect `log show --last 10m --style compact --predicate 'subsystem == "com.kaaaaai.SenseDraft" AND category == "ai-connection"'` and verify it records status, error type, and request ID without API keys or editor text.
3. In Shortcuts, record Analyze and Replace, save them, relaunch, and confirm they persisted. Click **Restore defaults** and confirm `⌥⌘E` and `⌥⌘Return` work.
   With Settings focused, verify Escape and ⌘W each close the window. While a shortcut box is recording, verify Escape cancels recording without closing Settings; verify ⌘W closes Settings and the global shortcuts still work afterward.
   In History, confirm saving is off by default. Turn it on, analyze an input, regenerate once, and verify one entry shows the latest suggestion. Replace a candidate and confirm that entry shows **Replaced** and the final English. Search for original and Chinese text, copy English from detail, delete one entry, and clear all history. Check that 7-day and 30-day retention remove older entries, No limit keeps entries beyond 100, and the selected period persists after relaunch. Turn saving off and confirm later analyses create no new entries.
   In the Review panel near the input, open the History button. Confirm the popover shows past suggestions, search finds them, detail shows original/English/Chinese, and Copy English works. Use Manage to reach the full History page.
4. In TextEdit plain text mode, type an awkward English sentence. Keep the cursor in that field and press Analyze without selecting text. Confirm the whole field appears in the panel, with improved English and Chinese meaning; typing alone should not open the panel or send a request.
5. Edit the Chinese meaning and click **Regenerate from Chinese**. Confirm the candidate updates while TextEdit remains unchanged. Press Replace and verify the complete field changes once.
6. Analyze again, then change the original text or focus a different external field before Replace. Confirm replacement is refused. Press Escape to dismiss the panel and confirm the source stays unchanged.
7. Repeat the read, copy, and replace checks in Sublime Text, Safari and Chrome textareas, contenteditable editors, and your main messaging editor. In Sublime, start with an unsaved disposable document: Analyze without preselecting text, confirm the entire text appears, and review the result. With **Allow Replace to remove text formatting** off in Settings → Home, confirm Replace is blocked for an editor flagged as formatted. Turn the setting on, relaunch, refocus the same editor, then press Replace. Confirm the text changes exactly once without another formatting confirmation. Record observed support in `compatibility.md`.
   In Feishu, use a fresh unsent draft after removing any text appended by an older SenseDraft build. Analyze and confirm an ordinary plain draft does not require a formatting confirmation. Click Replace in the review panel; confirm the panel hides while SenseDraft refocuses the same composer, then the original is gone and the suggestion appears exactly once. Repeat by returning focus to the composer and pressing the Replace shortcut. Do not click Send.
8. For the keyboard fallback, place a distinctive text and image on the clipboard before Analyze, then verify both clipboard representations are restored afterward. Repeat after Replace. Change the source text or switch windows before Replace and confirm it refuses to write. Check the caret position after Analyze; when no Accessibility selection range exists, it may move to the end. Clipboard-history apps may keep the temporary copy.
9. Test an already natural English sentence, Chinese input, mixed Chinese and English input, an empty field, and a password field. Confirm Chinese input produces natural English plus a Chinese meaning check. Confirm no unwanted replacement occurs. Check the rich text warning when the source has mixed formatting. Verify the review panel avoids a small focused input; drag the panel, then analyze again and confirm it reopens at the dragged position. Resize the panel taller and shorter; confirm the English and Chinese editors use the added height while the action buttons remain visible.
10. If you use ChatGPT plan, enable it in AI settings, authorize in your browser, then check the account and status in SenseDraft. Choose an available model, save, and run one analysis. The provider's streaming request and parser passed a live API call on 2026-10-12; confirm that the packaged panel now displays both English and Chinese. If the browser shows **Invalid authorization step**, record the diagnostics on that page. If SenseDraft shows a token-exchange HTTP error, record its OAuth error code. Also test **Cancel sign-in**, **Refresh models**, and **Disconnect**.

For a replacement that hides and reopens the review panel, inspect the recent unified logs with:

```sh
/usr/bin/log show --last 10m --style compact --predicate 'subsystem == "com.kaaaaai.SenseDraft" && category == "replacement"'
```

Each attempt has a short ID and stage names. These logs omit editor text, clipboard contents, window titles, prompts, and account data. Compare the first and second attempt IDs to locate the failing stage. The panel reappears when the replacement throws; it does not prove that a paste was sent.

For an intermittent Feishu capture error reporting that the editor window is unavailable, inspect the capture diagnostics with:

```sh
/usr/bin/log show --last 10m --style compact --predicate 'subsystem == "com.kaaaaai.SenseDraft" && category == "capture"'
```

The diagnostic reports only whether Accessibility exposed a focused element and the count of application windows after the short retry. It does not include draft text or window titles.
